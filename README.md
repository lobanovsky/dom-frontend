# dom-frontend

Веб-интерфейс администратора для [dom-backend](../dom-backend): дома, помещения, собственники с долями, жители, лицевые счета и плательщики. Работает и на компьютере, и на телефоне.

Прод: https://dom.lobanovsky.ru

## Стек

- Чистый JavaScript (ES-модули), без сборки и без зависимостей. Стиль и структура как в `dr-notif-frontend`.
- CSS без препроцессора: `tokens.css` (переменные), `base`, `layout` (каркас, мобильное меню), `components`.
- Caddy в Docker: отдаёт статику и проксирует `/api/*` и `/healthz` на `dom-backend:8080`.
- Тесты: встроенный `node --test`, только логика без DOM и сети.

## Структура

```
index.html
css/                     tokens, base, layout, components
js/app.js                вход: проверка сессии (GET /api/v1/auth/me), маршруты
js/router.js             History API, маршруты вида /premises/:id
js/api/client.js         единственный fetch: cookie-сессия, ApiError, 401 → вход, 5xx → тост
js/api/resources.js      CRUD-обёртки по ресурсам бэкенда
js/lib/                  логика без DOM: подписи перечислений, форматирование, доли, перевод ошибок API, тело запроса из формы
js/ui/                   форма, модалка, таблица, тосты, поле поиска физлица/юрлица, универсальный список
js/pages/fields.js       поля форм каждой сущности
js/pages/*/              страницы: обзор, организации, дома, дом, помещение, физлица, юрлица, счётчики
deploy/Caddyfile         прод: статика + прокси на dom-backend
dev/Caddyfile            локально: :3000, прокси на 127.0.0.1:8080
```

У физлица ФИО хранится тремя полями, а телефонов и email может быть несколько (первый — основной): в форме это список с кнопками «добавить» и «удалить». Поиск по физлицам идёт по ФИО, любому телефону и любому email. В формах собственника, жителя и плательщика поле физлица имеет два режима: «Найти в базе» и «Новое физлицо» (раздельные Фамилия, Имя, Отчество, дата рождения, списки телефонов и email); текст из строки поиска раскладывается по полям ФИО.

Удаление мягкое: запись помечается удалённой и пропадает из списков, но остаётся в базе. В любом списке и в блоках карточки помещения есть переключатель «Удалённые», где запись можно восстановить кнопкой. Нельзя удалить запись, пока у неё есть действующие связанные (дом с помещениями, помещение с собственниками, жителями или счетами): сначала удаляется зависимое. Удалённое помещение и дом открываются по ссылке с баннером «Запись удалена» и кнопкой «Восстановить».

Основной рабочий экран — карточка помещения `/premises/:id`: собственники (доли, периоды, сумма долей на сегодня), жители (родство, регистрация), лицевые счета с плательщиками, счётчики. Раздел «Счётчики» показывает общедомовые счётчики домов и счётчики помещений; у счётчика (воды, электроэнергии с одним–тремя тарифами) — карточка `/meters/:id` с историей показаний и расходом. В колонке последнего показания указан расчётный месяц зелёной меткой. На странице «Счётчики» можно выбрать месяц и отфильтровать приборы, по которым показания за него передали или не передали. У дома есть необязательное уникальное название: в таблицах, списках и выборах вместо длинного адреса показывается оно (адрес остаётся в карточке дома). У счётчика есть необязательное название («ИТП»; не уникально, ищется в поиске) — оно показано в первой колонке списка и в выборе общедомовых счётчиков услуги. Показания вводятся вручную; счётчик выводят из работы датой окончания, а не удалением.

В «Финансы → Электроэнергия» по умолчанию показан текущий календарный год, суммы по договорам и общий итог. Год переключается только стрелками влево и вправо; таблица показывает все его месяцы. Над таблицей отображается годовая сумма; при неполных данных в неё включаются только полностью рассчитанные месяцы с указанием их количества. Нажатие на месяц открывает детализацию. Кнопка «Контракты» позволяет добавить любое количество договоров, изменить название, номер, счётчики и тарифы из справочника, а также архивировать договор с сохранением прошлого расчёта. Неполные месяцы явно помечаются. Для однотарифных приборов выбирается один тариф, для многотарифных — тариф каждой зоны Т1–Т3; список содержит только тарифы в кВт·ч. Цены берутся из истории справочника за месяц расчёта. Требуется миграция backend `0046`.

Справочник «Услуги» (группа «Справочники»): коммунальные, эксплуатационные и дополнительные услуги организации, расчёт стоимости услуг счёта за месяц (кнопка «Расчёт» в карточке помещения), справочник «Тарифы» (цена, общая для нескольких услуг: меняется в одном месте), способ расчёта (по счётчику, по площади, площадь × норматив дома для отопления, фиксированно, суммой других услуг). Цены услуг ведутся только в справочнике «Тарифы» (периоды действия, история изменений): у услуги выбирается тариф, в её карточке видны цена сейчас и история цен. Услуга относится к типу лицевого счёта (ЖКУ, капремонт) и видам помещений; из карточки услуги её массово назначают подходящим лицевым счетам, а в карточке помещения у каждого счёта («Услуги») можно добавить разовую услугу на месяц.

На телефоне (ширина до 768px) меню выезжает сбоку, таблицы показываются карточками, а формы открываются шторкой снизу.

## Локальный запуск

```bash
# бэкенд (в ../dom-backend)
set -a; . ./.env; set +a; go run ./cmd/server

# фронтенд (в корне этого репозитория)
caddy run --config dev/Caddyfile     # http://localhost:3000
npm test
```

## Как устроен прод

- Фронтенд и API на одном origin: cookie `dom_session` HttpOnly, CORS у бэкенда нет.
- Цепочка: Traefik (TLS, Let's Encrypt) → Caddy в контейнере `dom-frontend` → `dom-backend:8080`.
- Контейнер подключён к двум сетям: `housekpr-network` (Traefik) и `dom-network` (бэкенд). Обе создаются вне этого проекта.
- `trusted_proxies private_ranges` в `deploy/Caddyfile` пропускает `X-Forwarded-Proto: https` от Traefik, поэтому бэкенд ставит cookie флаг `Secure`.
- Сертификат выпускает Traefik (резолвер `letsEncrypt`, HTTP-01) по labels в `docker-compose.yml`. Имя роутера `dom-frontend` и хост не меняйте: сертификат хранится в `acme.json` Traefik, а лишние выпуски упираются в лимиты Let's Encrypt.
- DNS: A-запись `dom.lobanovsky.ru` в Cloudflare в режиме DNS only (без проксирования).

## CI/CD

Workflow `.github/workflows/build-and-deploy-frontend.yml` запускается при PR и push в `master` и вручную:
1. `test`: `npm test`.
2. `publish`: образ `${DOCKER_USERNAME}/dom-frontend` с тегами `sha-<commit>` и `latest` в Docker Hub.
3. `deploy`: по SSH копирует `.env` и `docker-compose.yml` в `DEPLOY_HOST_PROJECT_PATH`, проверяет, что сети `dom-network` и `housekpr-network` существуют, делает `docker compose pull && up -d`, ждёт `/healthz` через Caddy (тем самым проверяется и связь с бэкендом), при неудаче откатывает прошлую версию.

Секреты GitHub Actions:

| Секрет | Назначение |
|---|---|
| `DOCKER_USERNAME`, `DOCKER_TOKEN` | Docker Hub |
| `DEPLOY_HOST_IP`, `DEPLOY_HOST_PORT`, `DEPLOY_HOST_USERNAME`, `DEPLOY_HOST_KEY` | SSH-доступ к серверу |
| `DEPLOY_HOST_PROJECT_PATH` | каталог проекта на сервере |

Бэкенд должен быть задеплоен раньше фронтенда: фронтенду нужен `GET /api/v1/auth/me`.

## Управление личным кабинетом собственника

Требуется бэкенд с миграцией `0040`. В списке «Физлица» кнопка «Личный кабинет» открывает подтверждение email, отключение доступа и отправку приглашения. Подтверждайте контакт после проверки личности; совпадение импортированного email само по себе доступа не даёт. Почта для входа уникальна, один аккаунт связан с одним физлицом. Для активированного кабинета используется восстановление пароля; менять логин этой формой нельзя.

В карточке дома кнопка «Приём показаний ЛК» задаёт включение и дни ежемесячного приёма по Москве. Расписание повторяется автоматически. При необходимости в раскрывающемся блоке задаются отдельные даты или запрет приёма для выбранного месяца; «Вернуть обычное расписание» удаляет исключение. Без включённого расписания или разрешающего исключения житель видит историю, но не передаёт значения. Требуется миграция `0042`. В истории счётчика источник `resident` отображается как «Личный кабинет».

Фронтенд кабинета находится в `../dom-resident`; его README содержит общий план и состояние реализации.

В списке физлиц администратор видит колонку «Личный кабинет»: «Не выдан», «Разрешён», «Зарегистрирован», «Входил», «Отключён» или «Вход недоступен» при отсутствии действующей собственности. Дата последнего зафиксированного входа показывается отдельно и не означает присутствие онлайн. Статусы загружаются одним пакетом на страницу; при ошибке показывается «Не загружен», без ложного вывода об отсутствии доступа. Для этой колонки нужен бэкенд с миграцией `0041`.

Форма использует галочку «Разрешить личный кабинет», кнопки «Сохранить» (без письма) и «Сохранить и отправить приглашение» (для первой регистрации). Для зарегистрированного аккаунта приглашение скрыто, логин доступен только для чтения. После сохранения список обновляется автоматически.

В разделе «Счётчики» кнопка «Экспорт показаний» открывает выбор расчётного месяца и скачивает Excel с типом и номером помещения, номером счётчика и показаниями. Выгружаются переданные показания индивидуальных приборов из всех источников; общедомовые приборы не включаются. Книга содержит отдельные листы ХВС, ГВС, Т1, Т2, Т3 с числовыми показаниями. Экспорт доступен и роли просмотра.

## Вода и водоотведение

«Финансы → Вода и водоотведение» (`/water`, для администратора) показывает календарный год со стрелками переключения, отдельные суммы воды и стоков, общий итог и суммы договоров (если их несколько). Годовой итог включает только полностью рассчитанные месяцы. По нажатию на месяц открываются показания каждого прибора, расход, применённые цены и причины неполного расчёта.

Кнопка «Договоры» позволяет добавлять, изменять и архивировать договоры Мосводоканала. Выберите вводные общедомовые счётчики холодной воды и два тарифа из справочника в м³ — на воду и водоотведение, одной организации. Включайте старый и заменивший его прибор: даты работы учитываются автоматически, в месяце замены расход суммируется. Подчинённые счётчики, уже учтённые вводным прибором, выбирать не следует. Объём водоотведения равен объёму воды. История цен редактируется в справочнике «Тарифы»; расход считается от последнего доступного показания. Пропуск месяцев отмечается предупреждением и датами замеров: весь расход относится к выбранному месяцу по его тарифам, без распределения по пропущенным месяцам. Отсутствие текущего показания, исходного показания для расчёта или цены делает расчёт неполным. Требуется backend с миграцией `0047`.

## Заявки на въезд и рабочее место охраны

Меню «Двор и паркинг» содержит «Заявки» (`/gate-access`) и администраторский раздел «Доступы» (`/gate-access/view`). Подменю также включает «Служебные доступы» (`/gate-access/service`) для сотрудников ТСН, подрядчиков и спецтехники без привязки к недвижимости. Доступ задаётся отдельно во двор, паркинг или обе зоны; отозвать зоны можно независимо, срок действия необязателен. Повторная запись с тем же телефоном объединяется с существующей: одна строка на каждую зону, уже выданная зона не дублируется. В заявках есть отдельный поиск по получателю, телефону, автомобилю и номеру помещения. Над схемой доступен поиск по полному номеру телефона: он показывает зоны, основания (недвижимость или служебный доступ), статус и есть ли действующий доступ по данным Dom; надпись помещения кликабельна и открывает выбранный объект на схеме. Напрямую устройства ELDES поиск не опрашивает. В разделе доступов выбирают тип объекта и дом, затем компактная схема показывает реальные помещения по этажам: номер этажа слева, шесть ячеек в строке, в углу ячейки — число действующих доступов. Нажатие на ячейку выводит справочное имя текущего собственника и список доступов с получателем, типом (собственник, арендатор, родственник или гость), телефоном и автомобилем; в этой таблице администратор может изменить имя, тип и автомобили, добавить доступ без заявки или закрыть доступ с указанием причины. Под списком действующих доступов можно включить «Показать отклонённые доступы» и удалить отдельную отклонённую заявку вместе с историей. Номера авто отображаются строчными буквами. Схема отмечает зелёным объекты с доступом собственника и оранжевым — если среди пользователей есть арендатор. Этаж берётся из карточки помещения; если он не заполнен, объект выводится в группе «Этаж не указан». Коммерческое помещение даёт доступ во двор. Доступен CSV-экспорт с группировкой по объектам. Раздел заявок доступен администратору и новой роли «Охрана». Администратор создаёт охранника в «Справочники → Пользователи». У охраны видны только заявки; API блокирует остальные разделы, включая финансы и физлиц.

По умолчанию открыта очередь «На проверке», которая обновляется раз в 30 секунд, пока вкладка видима и нет открытого диалога. Есть поиск по телефону, имени, номеру авто/помещения, фильтры зоны и статуса, постраничная навигация с выбором размера страницы; выбор запоминается как в остальных списках админки. «Открыть» показывает сведения о получателе, собственнике и всех выбранных объектах, комментарий и историю решений. Одна отправка из кабинета для квартиры и машиноместа отображается как две независимые заявки — на двор и паркинг; решения по ним принимаются отдельно. Сохранённые ранее сроки действия продолжают отображаться и учитываться. «Одобрить» повторно проверяет право собственности; причины отказа и отзыва необязательны. Когда житель отзывает доступ, карточка в кабинете скрывается сразу, а заявка появляется в очереди со статусом «Ожидает удаления с устройства». Администратор открывает её и нажимает «Отозвать доступ с устройства»; статус станет «Отклонено» после успешного ответа ELDES, при ошибке действие остаётся доступным для повтора. В диалоге решения получатель, телефон, зона и каждое помещение показаны отдельными строками. В списке есть статусы «На проверке», «Одобрено», «Ожидает удаления с устройства» и «Отклонено». Неактивные, отменённые и отозванные заявки относятся к «Отклонено»; конкретная причина видна при открытии. У группы со статусом «Отклонено» администратор может физически удалить её кнопкой «Удалить» после подтверждения; вместе с ней удаляется история, восстановить запись нельзя. Отказ выделен красным, ожидание — жёлтым, одобрение — зелёным. Диалог сгруппирован по получателю, объектам, автомобилю и заявителю; статус показан один раз, история свёрнута.

Одобрение синхронно добавляет телефон в устройства ELDES выбранной зоны. Жительский запрос на отзыв скрывает карточку сразу, а администратор отдельно подтверждает удаление с устройств. Для этих сценариев требуется backend с миграциями по `0054`.

### Автомобили и коммерческие помещения

Собственники коммерческих помещений могут подавать заявки во двор наравне с собственниками квартир. В одной заявке можно указать до 10 автомобилей кнопкой «Добавить автомобиль», удалить лишние строки или выбрать «Нет личного автомобиля». Список и карточка показывают все действующие машины; снятые с использования сохранены в раскрывающемся архиве. При создании новой заявки на основе прежней архивные машины не добавляются. Требуется backend с миграцией `0050`.
